# 统一数据规范（对应 3.3）

## 1. 统一标识
| 对象 | 编码规则 | 示例 | 数量 |
|---|---|---|---|
| 案例 case | `CASE-####`（4位顺序号） | CASE-0001 | 88 |
| 事件 event | `EVT-####`（一案一事件，与 case 同号） | EVT-0001 | 88 |
| 工作流程记录（文件2） | `REC2-####` | REC2-0001 | 596 |
| 触发—响应记录（文件1） | `REC1-####` | REC1-0001 | 348 |

- 以文件2（88案例）为超集统一编号；文件1的69案例全部可在文件2中匹配（同名），跨文件同一案例共用 case_id/event_id。
- case_id、event_id、record_id 三列已回写入两份 clean 文件；记录与案例通过 case_id 外键关联。
- 权威登记表：`data/processed/统一标识.xlsx`。

## 2. 情景要素 / 动作 / 知识统一编码
- **情景要素**（59条，取自受控词表）：事件 T1–T8、洪水来源 W1–W7、空间 S1–S9、人群 P1–P5、事故等级 G、政府/企业响应 ER/EN、疏散 E、设防 D、排水 PMP、失效构件 FC01–FC10。
- **处置动作 RA（12类）**：RA1 预警监测、RA2 接警上报、RA3 封口挡板、RA4 限速、RA5 停运、RA6 关站、RA7 广播疏散、RA8 封堵抢险、RA9 抽排、RA10 搜救、RA11 医疗、RA12 处置失效/盲目施救（负向）。
- **知识类别 KN（7类）**：KN1 事件事理、KN2 环境水文、KN3 设备设施、KN4 结构工程、KN5 人员行为、KN6 预警预案规则、KN7 通讯上报。

## 3. 标签归并
- 文件1原始"数据分类"自由标签共 **117 种**，存在同义、近义、复合（如"环境/设备状态类"）。
- 归并为 **7 个标准大类（A–G）**：A 环境与气象水文监测、B 设备设施状态监测、C 结构与工程安全、D 人员观察与行为、E 事件事理与事态演进、F 外部预警与应急指令、G 通讯与信息上报。
- 映射规则：剥离括号限定，取复合标签首成分归一；括号内限定词保留为"子类"以备细分。
- 117 个原标签均唯一对应一个大类（**无一例一对多冲突**）；完整对照见 `统一标识.xlsx/标签归并映射`。

## 4. 脱敏与引用
- 全量扫描手机号（1[3-9]xxxxxxxxx）、18位身份证号：**命中 0 条**，现有库以机构、事件、地点信息为主，无需额外脱敏。
- 案例结论一律注明来源与年份；补充公开资料登记来源—链接—获取日期—用途（见 `补充公开资料登记`）。
- 不确定字段一律留空并标注（如"资料不足/未明确"），不臆造数值。
