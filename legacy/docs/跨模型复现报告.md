# 跨模型复现报告：DeepSeek 与 通义千问 Qwen 的三角验证

> 对应章节：第5章 5.7.5；脚本 `code/50_qwen_replicate.py`；
> 数据 `results/runs/批量实验_千问抽检.csv`、`results/runs/跨模型_三向对比.xlsx`；
> 图 `results/figures/fig_跨模型复现.png`（图5-9）。

## 1. 目的与所要应对的效度威胁

第5章真实大语言模型（LLM）抽检仅基于 DeepSeek 单一模型。论文方法以 LLM 智能体为核心，
若安全结论只在一个厂商的模型上成立，则存在两类威胁：

- **构念效度威胁（模型特异性）**：观察到的"零死亡、早播报最关键、困难情景排序"可能是
  DeepSeek 训练偏好或安全对齐的产物，而非跨模型稳健的规律；
- **外部效度威胁（厂商泛化）**：无法说明结论能否迁移到另一个独立训练的模型。

应对方法是引入第二个**不同厂商、独立训练**的模型——阿里通义千问 `qwen-plus`
（OpenAI 兼容接口 `https://dashscope.aliyuncs.com/compatible-mode/v1`），
在与 DeepSeek 抽检**完全相同的 16 个分层配置**上各跑 1 个真实 run，
形成"启发式引擎—DeepSeek—千问"三向对比。

## 5. 结论与解释

**（1）安全关键结论完全跨模型一致。** 16 个配置下，千问、DeepSeek、启发式三者均为零死亡。
"开放站厅网络（具备向上层干区撤退条件）下不发生致死事件"这一核心结论不依赖任何单一模型，
致死对密闭车厢/区间微结构的依赖判断同样不受影响。

**（2）困难情景的相对排序基本一致。** 两个真实模型与启发式均为正相关，
且两模型彼此相关更高（ρ=0.713）；三者共同识别出 EXP-095、EXP-096、EXP-001 为最不利配置。
"早期信息最关键"在三类引擎下方向一致。

**（3）严重尾部的自救/救援比例存在模型差异——这是复现最重要的发现。**
DeepSeek 在严重尾部偏**乐观**（EXP-096 自救 0.883、EXP-095 为 0.938、EXP-001 为 0.986）；
千问则更**保守**（分别为 0.637、0.767、0.871），整体更接近启发式，
其决策日志显示千问在严重情景中更多选择观望、持续重估。
因此，第5章此前"启发式保守、LLM 乐观"的表述应修正为：
**跨模型稳健的是方向性结论（是否致死、哪些情景危险、早期信息最关键），
而严重情景下具体的自救/救援比例在模型间并不一致，不能把任一模型点估计当作真值。**

**（4）结果使用方式：三引擎包络。** 以启发式与千问构成相对保守一侧、DeepSeek 构成相对乐观一侧，
将自救撤离率/救援依赖率表述为三引擎包络区间，真实人群大概率落于其中。
这比单一模型的点估计更诚实，也比仅用启发式下界更有支撑。

**（5）证据等级升级。** 依据《抽检与证据分级规范》，关键结论原为"真实案例 + 单一模型方向一致"；
加入第二个独立厂商模型后，升级为"真实案例与 **≥2 个模型**方向一致"的①级强结论。
