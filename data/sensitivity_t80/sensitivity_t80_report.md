数据：仅规则模型，25 cid × 6 seed = 150 配对/版本；未调用 LLM，未改动冻结主模型，三版均为独立子类叠加。
输出：`results/sensitivity_t80/t80_all.csv`、`t80_summary.txt`；脚本 `_t80_sensitivity.py`；闭合核验 `_t80_verify.py`。

## 〇、随机状态初始化（差异与初始化有关，根因未完全定位）

首版全量出现的"FINE 1 人临界翻转""mild 组 FINE 有变化"，在同进程连续重复同一配置时不复现，提示差异与全局随机状态的初始化/消耗顺序有关。已在每次 `build()` 开头重置 `random.seed(seed)` 与 `np.random.seed(seed)`，使同一 cid/seed/version 在重置后可复现、与执行顺序无关。重置后重跑，BASE 与正式规则参考 `formal_main/rule/runs.csv` 最终计数 0 不匹配，FINE=BASE，三版死亡配对计数一致（仅计数，非个体核对）。

证据边界（不夸大）：
- 已保留：同配置重复运行结果、改变三版执行顺序后的结果、重置位置（`build()` 内全局种子重置）。
- 未定位到消耗全局随机数的具体模块前，只写"差异与随机状态初始化有关"，不断言根因已完全查明。
- BASE 最终计数匹配正式参考，只证明最终计数一致，不证明正式批次所有过程字段不受同类顺序影响。
- FINE 结论限定为"当前 150 个规则运行的最终计数未发生变化"，不推广为普遍的时间收敛证明。

## 一、版本定义与对比链（不把 WALK-BASE 当单一变量）

| 版本 | 检查间隔 | 转移方式 |
|---|---|---|
| BASE | 冻结 TimelineEvacModel：整分钟救援/死亡检查，bucket 每分钟 +rescue_rate(3.0 人/min) | 可达 comp 内 in 者瞬时引导出站（不占运力，记 rescued）；bucket 提取可达 stranded |
| FINE | 每 10s 检查一次救援/死亡；bucket 按 `rescue_rate×dt_s/60` 真实时间累加（频繁检查不放大运力）；lethal_s 按真实秒累积 | 同 BASE 的瞬时引导 |
| WALK | 继承 FINE 的 10s 检查 | 取消瞬时引导；comp 内 in 者引导沿 `path_to_exit` 实际步行到开放出口，记 evacuated 并打 `guided_exit` 来源标记；**窗末仍在可达域但未到出口者保留为 in（潜在可达，单列，不计入 safe）**；bucket 仅提取可达 stranded |

对比链：
- **FINE − BASE = 检查间隔**（二者都瞬时引导 comp 内 in → rescued）。
- **WALK − FINE = 转移方式**（同 10s 检查，仅瞬时引导 vs 实际步行）。
- **WALK − BASE = 检查间隔 + 转移方式联合**，仅作联合对照，不称单一变量消融。

## 三、配对结果

### FINE − BASE（检查间隔）
- 150 对 evacuated/rescued/stranded/deceased **最终计数全部一致（150/150）**，safe/death 非零配对 = 0。
- 三版总死亡 2073 人、有死亡的 31 个 run 计数一致。
- 结论限定：在当前 150 个规则运行、当前 25 情景下，整分钟检查加密到 10s（运力按真实时间换算、不放大）未使最终计数发生变化；这不是普遍的时间收敛证明。首版单例翻转已随种子重置消除，不作为边界效应。

### WALK − FINE（转移方式，同 10s 检查）
- **每个配对运行的死亡人数相同（150/150 计数一致，总死亡 2073 人不变）**；这只是计数一致，未按个体 ID 核对状态转换，不同个体之间可能发生抵消，不表述为"同一批个体死亡"或"无个体由安全离开转为死亡"。
- 安全离开比例由 FINE 的 0.9086 降至 WALK 的 0.8871（pooled，N=22,680），488 人到观察终点仍在站内（窗末未走完留 in，=潜在可达，150/150 配对 `d_safe = −in`，无 WALK 比 FINE 更安全的配对）。
- 同时发生分类重分配：FINE 瞬时引导 22.67/run @37.28 → WALK 步行出站 guided_exit 17.31/run @35.99；bucket 提取 12.87@46.15 → 14.39@49.77；自主疏散 self_evac 与出站时刻（≈19.8min）两版基本不变。
- 含义：实际步行替代瞬时转移未改变死亡人数，但改变了观察终点的安全离开比例与救援分类；该近似不是"仅改变标签"，它影响终点安全离开（488 人未计安全离开）。

### WALK − BASE（联合对照）
- 非零配对 32，构成与 WALK − FINE 相同（因 FINE=BASE）；同时含检查间隔与转移方式两项变化，不可单归于转移方式。

## 五、可写入论文的结论（收窄）

1. 在当前 150 个规则运行、25 情景、6 种子下，救援/死亡检查由整分钟加密到 10s（运力按真实时间换算）未改变最终计数；这是对当前测试集的计数观察，不是普遍的时间收敛证明。
2. 在所测试规则模型运行中，实际步行替代瞬时转移未改变死亡人数（每配对运行死亡人数相同），但使观察终点的安全离开比例由 0.9086 降至 0.8871，488 人仍在站内。因此该近似影响终点安全离开与救援分类，不能视为仅改变标签。
3. 安全离开口径统一为：自主出站 + 引导步行出站（guided_exit）+ 其他已完成救援转移（rescued）；计数上 evacuated（含 guided_exit）+ rescued。瞬时引导/引导步行人数不计入舟艇运力提取，guided_exit 不得并入自主疏散。窗末仍在可达域但未到出口者单列"潜在可达在站"，不兜底计入安全离开。

## 六、局限（不补猜，不外推）

- 两项敏感性只在规则模型、当前 25 情景、6 种子上检验，未在 DeepSeek/Qwen 上重复，不能外推到 LLM 决策结果。
- WALK 为引导式沿路径移动的替代实现，非完整人群行为重放；未做离开时间分布的完整分位统计，仅报告各类均值时刻。
- 分组（edge/high3/mild）为事后按规则模型死亡划分，非预先注册的物理严重性分层。
- 种子重置为本次敏感性脚本内部措施；BASE 最终计数与正式 #78 规则参考 0 不匹配只证明最终计数一致，不证明正式批次过程字段均不受同类顺序影响。
- 死亡"配对计数相同"未按个体 ID 核对状态转换，不排除不同个体间抵消；本报告不下"同一批个体死亡"的结论。
